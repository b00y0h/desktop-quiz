## E2E Flow Verification

### Flow 1: Admin Creates Quiz ✅

**Path:** Client → POST /api/quiz → store.createQuiz() → quizzes table

**Verified:** Quiz immediately readable, returns ID and code

### Flow 2: Admin Generates Submission Link ✅

**Path:** Admin → PATCH /api/quiz/[id] → store.generateSubmissionToken() → quizzes.submissionToken

**Verified:** Token immediately usable, status transitions correctly

### Flow 3: Worker Submits Desk Photo ✅

**Path:** Worker → POST /api/submit/[token] → Blob upload + store.addSubmission() → submissions table

**Verified:** Duplicate name detection, image stored in Blob, reference in Postgres

### Flow 4: Admin Closes Submissions ✅

**Path:** Admin → PATCH /api/quiz/[id] → store.closeSubmissions() → questions auto-generated

**Verified:** Questions created from submissions, idempotent operation

### Flow 5: Player Takes Quiz ✅

**Path:** Player → POST /api/quiz/[id]/submit → store.submitAnswers() → participants + answers

**Verified:** Score calculation, retake logic, foreign key integrity

### Flow 6: Player Sees Results ✅

**Path:** Player → GET /api/quiz/[id]/results → store.getLeaderboard() → sorted participants

**Verified:** Correct sorting (score desc, time asc), no stale reads
